# Обновление

Трекеры регулярно меняют вёрстку и домены, поэтому обновляться стоит своевременно —
исправления модулей трекеров выходят с каждой версией
(см. [changelog форка](https://github.com/PSlava/TorrentMonitor/blob/master/changelog.txt)).

У форка своя нумерация версий вида `3.3-fork.1`: цифра до дефиса — версия апстрима,
на которой основана сборка, после — номер сборки форка.

---

## Резервное копирование

Перед любым обновлением сохраните базу данных — в ней все раздачи, учётные данные
и настройки:

- **SQLite** — скопируйте файл базы (в Docker — содержимое тома `tm-data`);
- **MySQL** — `mysqldump torrentmonitor > tm-backup.sql`;
- **PostgreSQL** — `pg_dump torrentmonitor > tm-backup.sql`.

## Обновление в Docker

```bash
docker compose pull && docker compose up -d
```

Данные сохраняются в томах `tm-data` и `tm-torrents` — при правильно настроенных
томах обновление безопасно.

## Автоматическое обновление не используется

В **Настройки → Основные** есть тумблер «Автоматическое обновление TM», но в форке
он ни на что не влияет: проверка обновлений с `xml.tormon.ru` отключена. Механизм
апстрима скачивает `master.zip` из репозитория ElizarovEugene и распаковывает его
поверх приложения — для форка это означало бы затирание его собственных доработок
кодом апстрима. Поэтому обновление здесь только ручное.

## Ручное обновление (LAMP)

1. Сделайте резервную копию базы и `config.php`.
2. Обновите файлы: `git pull` в каталоге приложения либо скачайте архив
   [PSlava/TorrentMonitor](https://github.com/PSlava/TorrentMonitor) и распакуйте
   поверх старой версии (`config.php`, `config.xml` и каталог `torrents/` не трогайте).
3. Проверьте права: `chown -R www-data:www-data /var/www/torrentmonitor`.
4. Откройте веб-интерфейс — при необходимости TM обновит схему базы сам.

## Обновление базы данных

Изменения схемы применяются автоматически: `Migration::run()` накатывает недостающие
миграции при первом обращении к приложению после обновления. Ничего вручную делать
не нужно, но **бэкап перед обновлением обязателен**: автоматического отката схемы нет,
вернуться на старую версию можно только восстановлением из копии.

## Откат

- **Docker**: укажите предыдущий тег образа (`slashp/torrentmonitor:X.X-fork.N`)
  и восстановите базу из бэкапа, если схема успела обновиться.
- **LAMP**: `git checkout` нужного тега или разверните предыдущую версию файлов,
  затем восстановите базу из бэкапа.
