# Решение проблем

Частые проблемы и способы их устранения. Первым делом всегда загляните в раздел
**Ошибки** веб-интерфейса и попробуйте раздел **Тестирование** — они прямо указывают
на источник большинства проблем.

---

## Раздачи не проверяются / время синхронизации не обновляется

Движок (`engine.php`) не запускается по расписанию.

- **LAMP**: проверьте crontab (`sudo crontab -u www-data -l`) и запустите движок вручную:

  ```bash
  sudo -u www-data php /var/www/torrentmonitor/engine.php
  ```

  Ошибки смотрите в логе (`torrent_monitor_error.log`, если он указан в crontab).
- **Docker**: cron работает внутри контейнера (по умолчанию раз в час, переменная
  `CRON_TIMEOUT`). Проверьте логи: `docker logs torrentmonitor`.
- Разово запустить проверку можно из веб-интерфейса — раздел **Запуск**.

## Ошибка авторизации на трекере

- Проверьте логин и пароль в **Учётные данные** — и что вы можете войти на трекер
  вручную в браузере.
- На некоторых трекерах при входе с нового IP включается капча — зайдите в браузере
  с того же IP (или через тот же прокси) и подтвердите вход.
- Трекер мог сменить домен или вёрстку — проверьте раздел **Новости**
  и [обновитесь](Updating).

## Трекер недоступен (таймаут, connection refused)

- Провайдер блокирует трекер — настройте [прокси, TOR или зеркало](Proxy-and-Mirrors).
- Трекер за Cloudflare («проверка браузера») — подключите FlareSolverr/Byparr.
- Медленный прокси/TOR — увеличьте «Таймаут HTTP-запросов»
  в **Настройки → Расширенные**.

## «Есть ошибки» у темы, а в навигации «Ошибок нет»

До версии 3.3-fork.1 отметка об ошибке у темы жила отдельно от журнала ошибок:
после очистки ошибок кнопкой в разделе **Ошибки** записи удалялись, а пометка
на теме оставалась навсегда. Начиная с 3.3-fork.1 отметка снимается вместе с
записями журнала.

Второй источник расхождения: счётчик в навигации считался при загрузке страницы.
Если запустить проверку через **Запуск**, не перезагружая вкладку, новые ошибки
появлялись у тем, а цифра в шапке оставалась прежней. Теперь счётчик обновляется
при каждой смене раздела.

## Все трекеры разом «недоступны», хотя из браузера открываются

Типичный признак сломанного прокси: TM ходит **через прокси**, прокси рвёт
соединение, тело ответа приходит пустым — и каждый движок сообщает об этом
по-своему (`Не удалось получить RSS ленту трекера`, `Не удалось получить
страницу авторизацию трекера`, `Не могу получить доступ к трекеру`,
`Невозможно проверить новости`).

1. Откройте **Тестирование** — строка «Прокси …» показывает, прошёл ли
   проверочный запрос через прокси, и что именно не так.
2. В разделе **Ошибки** ищите записи от источника **Прокси**:
   - *Прокси-сервер отклонил авторизацию (HTTP 407)* — логин/пароль не подошли;
   - *Не удалось соединиться с прокси-сервером* — прокси недоступен, неверен тип
     (HTTP вместо SOCKS5) либо SOCKS5 закрыл сокет из-за неверной авторизации.
3. Если прокси требует логин и пароль — заполните **Настройки → Прокси →
   Авторизация** в формате `login:password`.
4. Проверить прокси в обход TM:

   ```bash
   curl -x http://login:password@ПРОКСИ:ПОРТ https://ya.ru/ -o /dev/null -w '%{http_code}\n'
   ```

   Пустой ответ и код `000` означают, что проблема на стороне прокси, а не TM.

## Раздача обновилась, но клиент её не скачал

- Проверьте подключение к клиенту в разделе **Тестирование**.
- Убедитесь, что «Директория для скачивания» указана так, как её видит
  **торрент-клиент** (частая ошибка при работе в Docker —
  см. [Торрент-клиенты](Torrent-Clients#пути-частая-ошибка)).
- qBittorrent: если включена защита CSRF/Host header validation, запросы TM могут
  отклоняться — отключите её или добавьте адрес TM в исключения.

## Скачиваются не все раздачи

Если при проверке обновилось сразу много раздач, а скачалась только часть —
подождите следующего запуска по расписанию: TM доскачает остальные.
Также проверьте лимиты на самом трекере (некоторые ограничивают число скачиваний
`.torrent` в сутки).

## Забыл пароль от веб-интерфейса

Пароль хранится в базе данных. Проще всего сбросить его прямо в БД —
например, для SQLite:

```bash
sqlite3 torrentmonitor.sqlite "UPDATE settings SET val='0' WHERE name='auth';"
```

— это отключит вход по паролю; затем войдите и задайте новый пароль в настройках.
Либо верните пароль по умолчанию (`torrentmonitor`):

```bash
sqlite3 torrentmonitor.sqlite \
  "UPDATE settings SET val='1f10c9fd49952a7055531975c06c5bd8' WHERE name='password';"
```

Для MySQL/PostgreSQL команды те же, только выполняются в соответствующем клиенте.

## Кнопка «Загрузить список» не отдаёт сериалы

- **Кнопка неактивна и подписана «Нет учётных данных»** — для этого трекера
  не заполнены логин и пароль в разделе **Учётные данные**. У baibako.tv нужен
  ещё и passkey. Список доступных трекеров считается при открытии страницы,
  поэтому после ввода учётных данных страницу нужно перезагрузить.
- **«Трекер не вернул список»** — трекер недоступен или учётные данные не подошли.
  Проверьте трекер в разделе **Тестирование** и загляните в **Ошибки**.
- **Ответа нет почти минуту** — это нормально для медленного трекера: TorrentMonitor
  последовательно проверяет сессию, логинится и запрашивает ленту. Каждый шаг
  ограничен таймаутом из **Настройки → Расширенные**; уменьшите его, если ждать долго.

## Интерфейс не изменился после обновления

Раньше браузер мог держать старую копию `scripts.min.js`: у статики нет заголовков
кеширования, и браузер считал файл свежим сутками. Страница при этом ломалась молча —
разметка новая, скрипты старые, новые кнопки не появлялись.

Начиная с 3.2.4-fork.2 к css и js добавляется метка версии по времени изменения файла,
так что кеш обходится сам. Если вкладка была открыта до обновления, перезагрузите
её принудительно (Ctrl+F5, в macOS Cmd+Shift+R). Убедиться, что страница свежая,
можно по номеру версии под логотипом.

## Белый экран / ошибка 500

- Проверьте лог веб-сервера (или `docker logs torrentmonitor`).
- Чаще всего не хватает PHP-модуля — сверьтесь со
  [списком требований](Installation-LAMP#необходимые-модули-php).
- Проверьте права на файлы: пользователь PHP должен иметь запись в каталог приложения.

## Режим отладки

Для детального разбора включите «Режим отладки» в **Настройки → Основные**
и запустите проверку из раздела **Запуск** — журнал покажет, что именно
происходит с каждым трекером.
