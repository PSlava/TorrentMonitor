# Прокси и зеркала

Трекеры часто блокируются провайдерами. TorrentMonitor предлагает несколько
инструментов обхода: глобальный прокси, индивидуальные прокси и зеркала для
конкретных трекеров и FlareSolverr/Byparr против Cloudflare.

---

## Глобальный прокси

**Настройки → Прокси** → «Использовать прокси»:

- **Тип прокси** — HTTP или SOCKS5;
- **IP и порт** — например `127.0.0.1:9050` (стандартный порт TOR);
- **Авторизация** — логин и пароль прокси в формате `login:password`.
  Оставьте пустым, если прокси не требует авторизации.

Через глобальный прокси идут **все** запросы TorrentMonitor к трекерам.

> **Если прокси требует авторизацию, а поле не заполнено** — прокси разрывает
> соединение (HTTP-прокси отвечает `407`, SOCKS5 просто закрывает сокет).
> Тело ответа приходит пустым, и движки трекеров сообщают об этом невнятно:
> `Не удалось получить RSS ленту трекера`, `Не удалось получить страницу
> авторизацию трекера`, `Не могу получить доступ к трекеру`. Начиная с
> 3.0-fork.2 TM дополнительно пишет отдельное предупреждение от источника
> «Прокси» и показывает состояние прокси на экране **Тестирование**.

## Индивидуальные прокси и зеркала (`config.xml`)

Тонкая настройка выполняется в **Настройки → Расширенные** — текстовое поле
содержит XML-конфигурацию (файл `config.xml`).

### Зеркало для трекера

Если трекер заблокирован, но у него есть работающее зеркало, TM может ходить
на зеркало, продолжая работать с раздачами как с оригинальным трекером:

```xml
<body>
    <mirror_address>
        <lostfilm.tv>my-lostfilm-mirror.example.com</lostfilm.tv>
    </mirror_address>
</body>
```

Для lostfilm есть и специальный вариант — трекер `lostfilm-mirror`
в списке трекеров: добавьте сериалы через него и укажите домен зеркала
в `mirror_address`.

### Прокси только для одного трекера

```xml
<body>
    <proxy>
        <lostfilm.tv>
            <use>yes</use>
            <type>socks5</type>
            <address>192.168.1.220:8118</address>
            <auth>login:password</auth>
            <mirror_address>google.ru</mirror_address>
        </lostfilm.tv>
    </proxy>
</body>
```

- `use` — `yes`/`no`;
- `type` — `http` или `socks5`;
- `address` — IP:порт прокси;
- `auth` (необязательно) — логин и пароль прокси в формате `login:password`;
- `mirror_address` (необязательно) — зеркало, на которое ходить через этот прокси.

Если `address` не указан, берутся адрес, тип и авторизация глобального прокси —
секция тогда работает только как переключатель `use` для конкретного трекера.

Секций может быть несколько — по одной на трекер. Индивидуальная настройка
имеет приоритет над глобальным прокси.

Секция трекера действует и на его поддомены: например, torrent-файлы kinozal.me
скачиваются с `dl.kinozal.me` и идут через прокси, заданный для `kinozal.me`.
Отдельная секция для поддомена, если она есть, важнее.

## TOR

Классическая связка для доступа к заблокированным трекерам — TOR как SOCKS5-прокси:

1. Установите TOR (пакет `tor`; в Docker — отдельный контейнер).
2. Убедитесь, что SOCKS-порт 9050 доступен для TorrentMonitor.
3. Укажите в TM прокси SOCKS5 `127.0.0.1:9050` (или адрес контейнера TOR).

Готовый рецепт для Docker (TOR + Transmission + TM в одной связке) описан в вики
Docker-проекта: [TOR-and-Transmission](https://github.com/alfonder/torrentmonitor-dockerized/wiki/TOR-and-Transmission).

Учтите, что через TOR трекеры отвечают заметно медленнее — при таймаутах
увеличьте «Таймаут HTTP-запросов» в **Настройки → Расширенные**.

## FlareSolverr

Некоторые трекеры прячутся за Cloudflare, который блокирует автоматические запросы.
[FlareSolverr](https://github.com/FlareSolverr/FlareSolverr) решает задачу Cloudflare в реальном
браузере и отдают TM готовые cookies.

1. Запустите FlareSolverr — обычно это Docker-контейнер, порт 8191:

   ```yaml
   services:
     flaresolverr:
       image: ghcr.io/flaresolverr/flaresolverr:latest
       container_name: flaresolverr
       restart: unless-stopped
       ports:
         - "8191:8191"
   ```

   Подойдёт и форк [Byparr](https://github.com/ThePhaseless/Byparr) —
   образ `ghcr.io/thephaseless/byparr:latest`, тот же порт.

   В `docker-compose.yml` форка Byparr уже описан под профилем `cloudflare`:

   ```bash
   docker compose --profile cloudflare up -d
   ```

2. В TM: **Настройки → Расширенные → FlareSolverr URL** →
   `http://byparr:8191` (рядом в compose) или `http://127.0.0.1:8191`
   (если TM работает не в Docker, а Byparr — на том же хосте).

Если поле пустое, обход Cloudflare не используется.

Проверить, что обход поднялся: `curl http://127.0.0.1:8191/health` —
должен ответить `{"msg":"Byparr is working!", ...}`.

Из трекеров, поддерживаемых ТМ, «проверку браузера» сейчас показывает **kinozal.me**:
без FlareSolverr его темы падают с ошибкой «Не удалось получить страницу трекера»
(`cant_get_forum_page`). Зеркала `kinozal.tv` и `kinozal.bz` не отвечают вовсе,
`kinozal.guru` работает без Cloudflare.

FlareSolverr открывает страницу в настоящем браузере и ждёт её полной загрузки,
а страницы раздач kinozal.me с рекламой грузятся до двух минут. Поэтому TM решает
проверку Cloudflare один раз на трекер за прогон, на той же странице без
параметров (около 10–15 секунд), а дальше скачивает страницы сам, с выданной
Cloudflare кукой `cf_clearance` и тем же User-Agent. Если кука перестала
действовать, страница запрашивается через FlareSolverr целиком, как раньше.
Torrent-файлы kinozal.me берутся с `dl.kinozal.me` — он Cloudflare не закрыт.

Настроенный прокси пробрасывается и в FlareSolverr — вместе с авторизацией,
если она задана. Учтите, что через прокси ходит браузер FlareSolverr, а не TM,
поэтому прокси должен быть доступен из его контейнера.

## Что выбрать

| Ситуация | Решение |
|---|---|
| Провайдер блокирует трекер | зеркало в `config.xml` или прокси/TOR |
| Заблокировано несколько трекеров | глобальный прокси или TOR |
| Нужен прокси только для одного трекера | индивидуальный прокси в `config.xml` |
| Трекер за Cloudflare («проверка браузера») | FlareSolverr/Byparr |
